**现象**：`git push origin --force master` → `remote: Permission to 25825825986/25825825986.github.io.git denied to 25825825986.` / `403`。

**诊断**：Token 本身有效（GitHub 已识别身份为 `25825825986`），但**对目标仓库没有写权限**。已排除仓库侧问题：`25825825986.github.io` 未归档（archived=false）、未禁用（disabled=false）、非 fork，owner 就是用户本人，分支 `main` + `master`（默认 `master`）。
→ 所以是 **PAT 权限不足**，典型两类原因：
- Classic PAT 生成时没勾 `repo` 作用域（只勾了 `workflow` 之类）；

**已做的改进**：`deploy-pages.yml` 新增 `Verify token has write access to target repo` 步骤，部署前用 `GET /repos/...` 检查 `permissions.push`，把难懂的 git 403 换成明确的中文报错（区分「访问不了」与「没有写权限」）。已用 js-yaml 校验通过。

**给用户的修复路径**：重建 Classic PAT（勾 `repo`）或修 Fine-grained PAT（选中目标仓库 + Contents: Read and write）→ 更新 Secret → 重跑。
