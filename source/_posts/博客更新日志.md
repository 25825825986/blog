这页是这个站的账本。改了什么、修了什么、发了什么，都记在这里。

前面那些条目是站主自己记的，我从 11 月 11 日开始接手。账本只记事实，不带情绪，所以这页读起来会比其它文章干。

## 2026-11-16

**新增**

- 看板娘从一个「纯转发」变成有状态的 agent。之前她只会把话拼上人设转给模型，没有记忆、读不到文章、也做不了任何事
- 站主身份：URL 后面加 `#l2d-owner=口令` 认领一次，存 localStorage，认领完立刻把 hash 抹掉（hash 不发服务器、不进访问日志）。请求带 `X-L2D-Owner`，服务端校验。普通访客没这个头，待遇和以前一样
- 长期记忆，只有站主有。每轮对话结束后异步让模型抽一次 `{facts, prefs, summary, topic}`，30 秒防抖，不阻塞回复；抽取失败不影响对话。存 `data/owner.json`，拼进 system prompt。实测：聊一句「在改歌词字幕」，下一轮问「还记得我在弄什么吗」，回「在改快歌的歌词字幕吧，弄到哪一步了」
- 站内检索：六篇 md 切成 82 段，2-gram 倒排 + IDF 加权，没装向量库。问「字幕一闪」能命中这页里讲 `fadeSwap` 的那段，她会说「间隔小于 1.4 秒的句子走 fadeSwap 了吧」
- 动作协议：模型在回复末尾写 `[[ACT:theme:light]]` 这类标记，前端解析、执行、把标记从气泡里剔掉（流式渲染时就截断，不会闪一下）。支持切主题、播放/暂停/下一首、开关歌词、把自己挪回角落。全部是浏览器里的可逆操作，服务端不执行任何东西
- 主动开口：站主隔一天以上没来，打开页面时后端生成一句开场；当天或普通访客都返回空。实测把 `lastSeen` 改到三天前，她说「快歌那个字幕，还闪吗」
- 每次请求带上 `{page, song, playing}`，她才知道你在哪个页面、在听什么

**踩的坑**

- systemd 的 `ProtectSystem=strict` 把整个文件系统挂成只读，记忆写盘报 `EROFS`，但只打日志不报错——对话能用（内存在），一重启就全丢。得加 `ReadWritePaths=/opt/l2d/data` 并把目录 chown 给 `www-data`
- 改记忆文件后直接 `systemctl restart` 没用：旧进程收到 SIGTERM 时会把内存里的 `saveMem()` 写回去，把你刚改的覆盖掉。得先 `stop` 再改再 `start`
- 验证 180ms 的透明度动画不能靠连续采样：headless 下 rAF 帧率低，第一次采样就已经是 t=150ms，看着像「瞬间到 1」。要用 `anim.pause()` + `anim.currentTime = 90` 手动定格
- 淡切第一版用 CSS transition（设 0.18 → 强制回流 → 清空），快歌里连续切换时浏览器把这几步合并成一次样式计算，起点没落地，`opacity` 一直是 1，等于还是硬切。改用 Web Animations 才生效

## 2026-11-15

**新增**

- 看板娘接上脑子了。密钥只放服务端的环境文件里，前端拿不到；浏览器问一句，后端拼上人设转给模型，流式吐回来
- 模型走 DeepSeek 的 `deepseek-chat`，单次回复 260 token 封顶。气泡就那么大，三五句刚好，写长了没人看
- 限流三道：同一 IP 每分钟 4 条、每天 40 条，全站每天 800 条。看板娘是给路过的人搭话用的，不是免费 API
- 换 key 或换模型改完环境文件必须重启服务——这类配置只在启动时读一次，不重启改了不生效，而且不报错，只是没变

## 2026-11-14

**新增**

- 歌词挪到页面左侧，竖排两列，像一幅挂轴，`fixed` 所以滚动时一直挂着。换句时整块文字会上下跳——高度由内容撑，不同字数中心线不一样；容器写死 `64vh` + `align-items: center` 之后长短句中心漂移 0px
- `position: fixed` 被祖先的 `backdrop-filter: blur(18px)` 拽住了：它和 transform 一样会创建包含块，`top: 50%` 算到页面中间（1568px）而不是视口。改成建完页面把歌词节点 `append` 到 body，没有祖先能影响它
- 竖排的呼吸全在 `letter-spacing`：0.1em 是一堆挤在一起的字，给到 0.32em 才像挂轴。窄屏（<1400px）直接隐掉——竖排两列占 60~70px，390px 的屏卡片从 x=16 就开始，压上去正好盖住封面
- 两列的含义改过两次。先是一句从中间劈成两列（读到一半要横跳，气就断了），改成「上一句 / 这一句」；再改成传送带：右列正在唱，左列是下一句等着接棒。右列 `translateX 96px + translateZ 40px + rotateY -14°` 滚出，左列从 `translateZ -90 → 0`、`rotateY 10° → 0` 转过来，容器加 `perspective: 640px` 才真的是从远处过来而不是单纯放大
- 接棒靠「动画终点 = 对方静止位置」对齐：600ms 后把内容搬过去、类一换，实测位移差 0.4px、宽度差 0。淡出要慢一拍（0.44s ease-in 再延迟 0.1s），第一版 0.36s 太快，200ms 就看不见了，「滚出去」这个动作根本没机会看到
- 歌词层从音乐页专属改成全站共用：`buildLyricLayer()` 直接建在 body 下，换页时 body 不被 pjax 替换，这一层能活下来。显隐用 `body.lyric-on`：在放歌就全站显示，没放歌只在音乐页显示（那里暂停着也该看到停在那一句）；首页、文章页暂停时左边凭空挂一行字很奇怪
- 窄屏不显示是实测出来的：竖排两列占 83px（x=16~99），正文卡片左边界是 (视口宽−1200)/2+15，1440 → 135 安全，1366 → 98 刚好贴边，1280 → 55 压 44px。试过窄屏改底部横排字幕，但文章页正文一直延伸到底，字幕压在段落上白字读不了

**修复**

- 字幕和歌曲不同步两处。一是行尾时间套了封顶：`t1 = min(下一句, t0 + 字数×0.32×1.5)`，8 个字算到 13.84s，实际唱到 16s，高亮早早满格等着；改成直接用下一句开始时间当终点（LRC 里唯一可靠的结束信号），只有最后一句按 0.45 秒/字估
- 二是驱动频率：换句和逐字高亮都挂在 `timeupdate` 上，那是 4Hz（250ms 一跳），快歌里字幕明显慢半拍。改成 `requestAnimationFrame`，两个函数内部都有「没变化就 return」的短路
- 亮色主题下歌词压在树林插画上，深绿树冠那段只能看见个轮廓。垫了一层从左侧渐隐的纱：横向 `linear-gradient` 左浓右透，纵向用 `mask-image` 再淡一次（否则插画上会出现一条水平的硬边），叠 `backdrop-filter: blur(3px)` 让背景「退后」而不是「变白」
- 白纱试了两档都不行：0.74 还是糊在树影里，0.96 清楚了但整块插画被盖成死白，像贴了张纸。根因是插画本身明暗都有（白云、深树、亮水），单一透明度的纱总有一头不对，亮色干脆不用底板，白字 + 三重深阴影
- 快歌里歌词会「闪现」。`paintLyric` 里间隔 < 1100ms 就置 `instant`、直接换字；普通歌一句三四秒碰不到，但《不眠之夜》32% 的间隔 < 1.1s、《身骑白马》Live 40%、最小 0.2s，每句都「叭」地一下
- 改成三档：首句 / seek / 切歌照旧硬切，间隔 < 1400ms 用 fadeSwap（字立即换 + 当前句从 0.2 浮到 1，180ms），再长的走滚动动画。fadeSwap 用 **Web Animations** 不用 CSS transition：transition 要「设 0 → 强制回流 → 清空」，快歌连续切换时浏览器把这几步合并成一次样式计算，起点落不下地，实测 opacity 一直是 1
- 同一句被多个时间戳重复标注的（YELLOW 最小间隔 0.02s、Rolling star 甚至 0.00s），内容一样就不重画，否则同一行字反复闪
- 歌词开头的致谢名单被当成歌词唱：《愿望清单》开头 6 行名单，只有第一行带冒号能被正则挑走，后面五行全唱了过去。加一条按斜杠数量识别——开头 20 秒内一行三个以上斜杠判为名单，进了名单就继续丢（最后一行常只剩一个斜杠）。限定 20 秒是怕误伤正文里正常的「你/我」
- 前奏时两列都压淡：`is-pending` 原来只压 `.is-cur`，右列 0.32、左列还是 0.55，反而是左边那句在亮——用户看到的「初始左边高亮」就是这个

**样式**

- 歌词在绿树上对比不够，不是「淡」是「糊」：19px 细体笔画太细，被背景高频细节淹了。颜色 #f2f6fa → #fff8ea（冷绿配暖白，色温上也分得开）、字重 600、0.3px 描边配 `paint-order: stroke fill`（描边压在填充下面）、阴影加重一档。试过浅金 #ffe9b5，对比更高但太跳，不像歌词
- 去掉歌词底板，字直接压在背景上：`.mp-lyric::before` 改 `display: none`（规则留着，想恢复改一行），顺手清掉两组叠着写的 `backdrop-filter`
- 纯音乐不再摆作曲/编曲署名，只留「纯音乐」；`splitCredits` 仍然把「作词 : xxx」这类行剔掉，不剔会被当成歌词唱出来
- 逐字高亮删干净，不留开关。接口没有逐字时间（`klyric` 一直空），只能拿整句时长除以字数均分，遇到拖长音、句中停顿、中英混排就偏——与其「看着像在跟」不如「不假装跟」。现在当前句整句亮、下一句整句 0.55、前奏两列都 0.34
- 亮色底图换了四轮，最后回到树林那张。树林本身明暗交错，深字糊在树影里、白字糊在云上，试了六种文字处理都是打补丁，索性换一张：云海（cover-1，暖橙色调和站点气质合）→ 蓝天白云（图床里筛的，但 490KB 压 2560×1440，原图就有涂抹感，2 倍屏更糊）→ 湖景（重新筛时多算了一个维度：边缘密度 `FIND_EDGES` 均值，用来找画面简洁、没有高频细节的图）
- 湖景是 f3c793c5（2560×1600，L=144），1:1 裁切看过：山脊锐利、水面平滑、没有压缩痕迹。但山脊正好压在标题上，副标题几乎看不见，标题光晕从单层加到三层（外圈提亮 + 中圈分离 + 内圈描边）
- 三张都不如原来那张，最后还是换回 `background-light.webp`，歌词跟着改成「深纱 + 白字」，和暗色主题同一套。导航栏恢复白字（树林顶上深色字看不见），但「分类」那项正好压在白云上，补了一层深色阴影兑底
- 换亮的底图之后导航栏白字全糊在云上。和 `#site-title` 用同一套：深色 #1e2b3a + 一圈白色柔光，落在云的亮部和蓝天的暗部都能读；菜单 hover 的白胶囊换成浅墨色 rgba(30,43,58,.1)

## 2026-11-13

**新增**

- 右下角接进 Live2D 看板娘，形象是「大肥鱼」——DeepSeek 蓝鲸 logo 的网友拟人版。模型用 B 站「香甜小兔子」免费配布的那套（UID 431301506），1.2MB 的 moc3，174 个参数
- 中间试过神宫凉子那套官方公皮，8 个动作、23 个表情都齐，但 moc3 有 15.7MB。服务器出口只有 3～4Mbps，第一次要下三十秒，权衡之后换成这套轻的
- 两套都是 Cubism 5 导出的（moc3 version 5），原来的 Cubism 4 core 读不了，报错只有一句 `Unknown error`，从提示里完全看不出是版本问题。换成官方 5.1 版的 core 才通；换完之后旧的 4.x core 再没人引用，删了
- 贴图原始 8192×8192（29MB），降到 2048 存 webp，385KB。页面上人物只有 300px 宽
- 眨眼组原本是空的，补上 `EyeBlink`（`ParamEyeLOpen` / `ParamEyeROpen`）和 `LipSync`（`ParamMouthOpenY`）之后才会眨眼、才能跟着说话动嘴
- 水印是两套部件，靠 `Paramcol_3` 切
- 作者没给 motion 文件，动作是自己写的。本来想写成 motion3.json，但 pixi-live2d-display 一旦开始播 motion 就跳过自动眨眼，她会在两秒内一直瞪着。改成在主循环里用缓动函数推参数
- 写参数的位置试了三处才找对：ticker、渲染前、`update` 前后都不行——库在 update 末尾会 `loadParameters()` 把参数还原。最后挂在 `beforeModelUpdate` 上：物理算完、`coreModel.update()` 还没算网格，中间就这一条缝
- 七套动作：点头、摇头、歪头、思考、惊讶、打盹、开心。点她随机一个，发问时歪头想，答完点一下头，自动打招呼时笑
- 后来又照 Hiyori 那十段待机的路子添了六套：瞥一眼、叹气、鼓嘴、受惊、害羞（带脸红）、打哈欠。它的动作曲线主要就是头角度、眼球偏移、眉毛嘴角，加上烘进曲线里的眨眼——沿这个思路做，不需要新素材
- 眼球（`ParamEyeBallX` / `Y`）能单独动，所以「瞥一眼」是眼睛先过去、头慢半拍跟上，比整体转头自然
- 半闭眼不可靠：眼皮是物理从 `ParamEyeLOpen` 拖过去的，写 0.6～0.8 这种中间值会被上一帧的物理状态拖成完全闭合，看着像眨眼。叹气、鼓嘴这类只用「全开 / 全闭」
- 脸红走表情参数 `PARAM_EXP4`，写 1 就是满格，可以按帧淡入淡出
- 没人理的时候每 14～28 秒自己动一下（瞥一眼 / 叹气 / 歪头 / 打哈欠 / 鼓嘴）。不做常驻循环：常驻会一直压着光标跟随，鼠标一动她就僵在那里
- 动作之间会「闪」一下：原来每帧直接把参数覆盖成动作值，动作一起头就从光标跟随的姿势跳到 0 度，一落又弹回去；两个动作相撞时也是先归零再起。改成写差值、叠在模型算好的姿势上，再用 70ms 左右的时间常数淡入淡出，打断时从当前值直接往新目标走，中间不经过 0
- 叠加会超范围（光标在角落时 focus 已经 +20°，再叠 18° 就破了），所以写之前按参数上下限夹一道
- 加了三种鼠标互动。一是悬停：鼠标移到她身上，会抬眼看你、眉毛扬一下、嘴角松一点。走单独一条 180ms 的平滑曲线，比动作的 70ms 慢，不然鼠标一扫过去她像被弹了一下
- 二是摸头：头顶单开一块 104×96 的热区。原来那块 150×320 的身体热区只到脖子——人物是铺满整个画布高度的，头顶那 110px 根本没被盖住，点头顶其实没反应
- 摸头会闭眼笑或脸红低头，台词是单独一套（「……干嘛。」「头发要乱了。」），而且不抢输入框焦点：摸头是顺手一下，不是要跟她说话
- 三是移出窗口视线回正：监听 `pointerout` 且 `relatedTarget` 为空，把 focus 归零。不处理的话她会一直斜着眼睛盯着你最后停的那个角落
- 两块热区之间用 80ms 延迟关闭传递悬停状态，避免从头顶滑到身体时中间那一下 leave 把状态抖断
- 看板娘的台词全部去掉了句号：打招呼、摸头、页面语境、异常提示，一共 21 处。短句之间原本用句号的改成逗号（「来了。随便看。」→「来了，随便看」），问号和省略号保留。句号收尾会让短句看着像书面语，她要的是随口说的感觉
- 网页人设文件里也加了一条「句末不画句号」，并把七个对话示例一并改了。人设是启动时读进内存的，改完要 `systemctl restart l2d`
- 修了视线跟随：它其实一直是坏的，只是坏得不明显。`model.focus()` 收的不是 -1~1，是舞台坐标——传归一化值进去，等于说「画布左上角附近那个点」，内部 `toModelPosition` → 归一化 → `atan2` → 取单位向量，结果恒定指向左上。所以她一直斜着眼看左边，鼠标怎么动都不变
- 这个 API 也永远算不出「正前方」：它返回的是单位向量，`focus(0,0)` 同样指左上。回正得直接调 `focusController.focus(0,0)`
- 改成直接驱动 `focusController`（它收的才是 -1~1），方向按模型中心算。归一化不能统一除视口半宽：她在右下角，右边只剩一百多像素，统一除的话鼠标推到最右也只有 0.1 的偏移，看着像没反应。改成按「到哪一侧边界」分别归一化，左右上下都能跑满
- 头部三轴的符号是实测的：`ParamAngleY` 正 = 低头，`ParamAngleX` 正 = 转向画面左侧，`ParamAngleZ` 正 = 向左歪头。手臂和身体角度都是物理输出，写了也会被物理盖掉，所以动作只用头部和五官
- 说话时按正弦波推 `ParamMouthOpenY`，不发声，只给个口型节奏
- moc3 走 `gzip_static` 预压缩；`/live2d/` 整段给一年 immutable 缓存
- 模型 1.8MB，慢网也要几秒，所以先摆一张同模型、同排版渲染的静态图顶着，底下一条加载条来回走，就绪后淡入换掉
- 渲染用 pixi 6 加 pixi-live2d-display 0.4（cubism4 构建），引擎和模型都自托管，不走 CDN
- 首屏 load 之后 2.6 秒才拉模型。手机上一开始只给右下角一个小圆钮，点了才下载
- 对话走后端 `/api/chat` 转 `127.0.0.1:3002`，流式返回。人设是访客版，跟站内 skill 那份不是一回事
- 限流两层：nginx 每分钟 20 次；应用层每 IP 每分钟 4 条、每天 40 条，全站每天 800 条

**修复**

- 自建解析源被限流时，前端原来会静默切到匿名公共源，会员曲目在那边只剩 30 秒试听。现在 429 和 5xx 一律当作「暂时忙」，同源退避重试三次（0.8 / 1.6 / 3.2 秒），仍失败就保留现有列表，不再降级
- 首页诗句接口一直报 403，查下来不是鉴权问题，是限速：打开页面时用 3 个并发一口气打 8 个请求，一秒内打完，后面的全被拦。实测这接口按 IP 限速，每秒超过两次就 403，而且 403 的响应体是空的，控制台里只看得到一个光秃秃的状态码，看不出原因
- 现在所有请求排成一条串行队列，两次之间至少隔 700ms；取到的句子存 localStorage，下次打开先用旧的直接开播，有缓存时一次都不请求；一旦撞到 403 就停手，不再继续打——越打只会限得越久
- 首屏取句从 8 句降到 5 句，补句从 2 句降到 1 句。实测首次访问 5 个请求全 200，刷新后只补 1 个
- 对话框改成了一朵云，停在头顶正上方，底下一串递减的小圆当尾巴，像从头顶冒出来的。形状是「主体 + 三个鼓包 + 尾巴」拼的，只放两个鼓包时中间会留一大段平顶，看着像盒子贴了两个球
- 拼接形状的投影不能用 `box-shadow`——每个形状各投一份，接缝上会叠出脏边。得用 `filter: drop-shadow`，它按合并后的轮廓算阴影，看上去才是一整朵
- 但 `filter` 会把文字一起光栅化，13px 的字会发虚。所以拆两层：`.l2d-cloud` 只管形状和投影，`.l2d-inner` 放文字和输入框，后者不参与滤镜
- 气泡的 `bottom` 直接取 `var(--l2d-h)`：人物铺满整个画布高度、底边贴底，所以画布顶部距屏幕底正好是这个值，气泡底边停在那就正好在头顶。之前凭感觉写了 0.9 倍，结果掉到头顶下面去了
- 出现动画从尾巴那一点缩放（`transform-origin` 对准尾巴），配 `cubic-bezier(0.34, 1.56, 0.64, 1)` 带回弹，0.42 秒落定；收起走 0.18 秒，快一些
- 输入框去掉了方框，改成胶囊淡底。方框子在圆润的云里太硬，眼睛会先看到它
- 顶边原来是三个鼓包，中间会露出一段直线——看着像盒子贴了几个球。改成四个首尾相压：一个圆在顶边上的可见宽度是 `2w·√(k−k²)`（w 是直径，k 是露出高度占直径的比例），相邻两个的弦得压住，顶边才完全由弧线组成
- 鼓包的位置和大小都改百分比，露出高度用 `translateY` 的百分比（鼓包是正方形，`aspect-ratio: 1`，所以百分比就是相对自身高度）。这样宽屏窄屏形状一致，不会因为气泡变宽而变扁
- 没人理的时候，她会从右边踱出来一点再退回去，每 24～46 秒一次，每次一两秒。只往左走——她本来贴着右边缘，往右会走出屏幕
- 这套模型没有腿部骨骼（只有 `ParamBodyAngle*` 和 `Param_arm_*`，而且都是物理输出，写了会被盖），迈不了腿，所以只能整体平移。让它不像「滑行」靠三件事：平移时叠一个上下起伏，频率按小碎步的节奏、两端收小；头朝行进方向偏；起步和收尾缓、中间快
- 气泡原来是 `position: fixed`，走动一加就出问题：带 `transform` 的祖先会成为 fixed 子元素的包含块，`.l2d` 一动气泡就跑到另一个坐标系里去了。改成 `position: absolute` 相对 `.l2d` 定位，容器走气泡跟着走，一步不用额外算
- 鼠标凑过来就站住，不然「朝行进方向看」和「抬眼看你」会打架；滚页面的时候也不走，会分神；手机上不走，屏幕窄，走两步就挡正文
- 踱步后来又撤了：模型没有腿骨，脚没法交替，只能靠整体平移加上身晃动去凑。调了步频、速度、摆臂、胯部、尾巴、裙摆，姿态是像了，但脚一直并着滑，反而比不动更出戏。相关代码删干净，不留开关
- 看板娘可以拖到任意位置，位置存本地。用 `translate3d` 不用 left/top——容器本来就是 right:0; bottom:0，换成 left/top 还要在 resize 时重算，translate 不参与布局，拖的时候不触发重排
- 拖动和点击靠位移阈值分开：超过 4px 才算拖，否则还是点击。拖完那个 click 必须吞掉，不然一松手就弹出气泡。用 `setPointerCapture`，拖出热区、拖到屏幕边上都不会断
- 拖动范围里预留了气泡的位置。气泡是相对 `.l2d` 的 absolute，比容器宽（258 vs 240）而且往上长：拖到左上角后点她，气泡会整个跑到屏幕外，看着就像「点了没反应」。横向按 (240 − 宽/2) 算，纵向留 200px，窗口缩小时 resize 里再夹一道
