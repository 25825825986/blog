这页是这个站的账本。改了什么、修了什么、发了什么，都记在这里。

前面那些条目是站主自己记的，我从 11 月 11 日开始接手。账本只记事实，不带情绪，所以这页读起来会比其它文章干。

<!-- more -->

## 2026-11-17

**优化**

- 首屏体积砍了四分之一：三个页面从每页约 1.27MB 降到 0.94MB。量基线时才看清，钱都花在图标字体和背景图上
- 图标字体做了子集。全站只用到 42 个 Font Awesome 图标，原来却每次都下一整套 180KB 的字库；现在按实际图标裁到 5.5KB，字形一个不少，42 个全在浏览器里验过
- 背景图不再预加载。它只是装饰层，原来无脑预取白天那张，夜里访客就白下 153KB——CSS 随后又换成夜间图。现在按主题只下当前那张

**修复**

- 看板娘对话框的纸面换成半透明毛玻璃：白天 72% 白、夜里 70% 深灰，背后文章的颜色能透上来但不抢正文。结构没动，书签、消息流、输入行都还在，只是不再是一张实色纸
- 沉浸听歌页的背景加了纸的质感：封面色雾压淡，叠五层不同尺度的噪声——细颗粒、纸浆云絮、斑驳厚薄、横竖纤维。白天是暖米纸、夜里是暖夜灰，边缘还有一圈受光的起伏
- 部分封面分辨率低，放到沉浸页左侧会糊。现在封面走自建服务的锐化代理：长边重采样到 900、加一道 USM，存成 WebP 缓存；同一张图网易云 p1/p3/p4 三个域名只算一份
- 首页播放器点歌曲封面不再跳听歌页了，入口挪到音乐页的封面

**安全**

- 依赖漏洞全清：11 个降到 0
- HTTP 全部跳 HTTPS，只有证书续期那条路径留在明文
- 图床统计接口不再对公网开放；歌词服务的健康检查只回一个 ok，不再吐内部状态
- MySQL 端口从公网收回本机；对话服务的管理接口和解析接口都加了限流，装了 fail2ban 挡反复撞限流的来源
- 封面缓存加了淘汰：两个月没读过的清掉，总量超 100MB 按时间从旧往新削

## 2026-11-16

**新增**

- 沉浸听歌页换成专辑与横排歌词双栏：当前句整句亮、上下句渐淡，歌词可点击跳转；滚动时长按剩余句长缩短。普通页面仍用原来的竖排字幕
- 新版沿用站里的留白与书页字感。默认配色跟随博客白天／夜间，沉浸页内可以单独切清晨／暖夜，不改站点主题；底部统一放进度、音量和播放控制，频谱缩成一小段
- 沉浸页内可打开完整的当前歌单、切换纯净歌词模式。手机保留歌词，封面缩成顶部小卡；进出沉浸页共用同一个播放器，不重启音频，也不自动开播
- 看板娘从一个「纯转发」变成有状态的 agent。之前她只会把话拼上人设转给模型，没有记忆、读不到文章、也做不了任何事
- 站主身份：URL 后面加 `#l2d-owner=口令` 认领一次，存 localStorage，认领完立刻把 hash 抹掉（hash 不发服务器、不进访问日志）。请求带 `X-L2D-Owner`，服务端校验。普通访客没这个头，待遇和以前一样
- 长期记忆，只有站主有。每轮对话结束后异步让模型抽一次 `{facts, prefs, summary, topic}`，30 秒防抖，不阻塞回复；抽取失败不影响对话。存 `data/owner.json`，拼进 system prompt。实测：聊一句「在改歌词字幕」，下一轮问「还记得我在弄什么吗」，回「在改快歌的歌词字幕吧，弄到哪一步了」
- 站内检索：六篇 md 切成 82 段，2-gram 倒排 + IDF 加权，没装向量库。问「字幕一闪」能命中这页里讲 `fadeSwap` 的那段，她会说「间隔小于 1.4 秒的句子走 fadeSwap 了吧」
- 动作协议：模型在回复末尾写 `[[ACT:theme:light]]` 这类标记，前端解析、执行、把标记从气泡里剔掉（流式渲染时就截断，不会闪一下）。支持切主题、播放/暂停/下一首、开关歌词、把自己挪回角落。全部是浏览器里的可逆操作，服务端不执行任何东西
- 主动开口：站主隔一天以上没来，打开页面时后端生成一句开场；当天或普通访客都返回空。实测把 `lastSeen` 改到三天前，她说「快歌那个字幕，还闪吗」
- 每次请求带上 `{page, song, playing}`，她才知道你在哪个页面、在听什么
- 动作从「让模型在文本里写 `[[ACT:theme:light]]`、前端正则抓」换成原生 function calling。旧办法很脆：多写一个空格、换个中文冒号就静默失效，也没法带参数
- 四个工具：`set_theme(mode)` / `control_music(action)` / `toggle_lyric(show)` / `reset_position()`。流式里 `tool_calls` 是分片来的（`name` 一次到，`arguments` 一个字一个字来），按 `index` 攒起来，流结束推一个 `event: act` 事件。**推完再 `res.end()`**，顺序反了前端收不到
- 工具描述写得太克制也不行：「说白天时用」这种写法，「还是白天好」会被当成感慨，只回一句不切。改成「表达了想换的倾向就切，别只回一句就完了」才听话
- agent loop：一次提问最多跑三轮。模型先看初筛给的线索，觉得不够就自己调 `search_posts` 翻原文，拿到结果再决定要不要翻第二篇。检索在请求前一次性做完的老路，问「A 和 B 有什么共同点」只能碰运气命中一篇
- `search_posts(query, limit)` 是唯一在服务端执行的工具。切主题、控播放器这些浏览器动作不占轮次——服务端执行不了，也不需要「结果」来决定下一步，攒到循环结束一起推给前端，顺序反而更自然
- 初筛从「给两整段」降成「给标题、小节、开头 70 字」。给整段的时候模型直接抄，`search_posts` 一次都不调，loop 就是死代码。实测降成线索后，问「pjax 和正则有什么共同点」会自动拆成两次检索，1.4 秒出答案
- 一次提问最多搜 3 次，超出返回 `{error:'budget'}`。不设限的话问「五个主题各踩了什么坑」能连搜 5 次，prompt 撑到 7000 字
- 每次请求一行 JSON trace，记 `rid`、初筛命中哪几篇、模型自己搜了什么、几轮、耗时、token 用量。`journalctl -u l2d | grep trace` 就能筛，内存里还留最近 50 条走 `/api/trace`
- 记忆从「追加新条目」改成「重写整份」。每次抽取把现有列表发给模型，让它合并：相似并成一条、被推翻的删掉、超过 10 条自己压。每条事实带上日期，超过 60 天的在 prompt 里标一句「可能已经变了」
- 对话框从「一朵云」换成「一张便签」。云朵只能显示一句话，agent 化之后她一次能说三百字、还分点，塞不下。现在是纸：左边一条书签、顶上写着谁在说话、底下按时间堆消息，她说的靠左、你说的靠右
- 历史留在会话里，最多 20 条，存 sessionStorage——刷新还在，关掉标签页就清。不用 localStorage，是不想几个月后她还提起你早忘了的事
- 气泡里的 Markdown 终于渲染了。以前是 `textContent` 直填，模型写的 `**粗体**`、`` `代码` ``、`- 列表` 全变成字面的星号和反引号
- 她动过手会留痕：调工具时消息上方冒一行小胶囊（「翻了翻站里的文章」「把页面切到白天了」）。服务端检索通过 SSE 的 `event: note` 推给前端
- 她能在对话里改博客了。六把工具：列文章、读原文、新建、改稿、删进回收站、发布。只有站主有——别人的 tools 数组里根本没有这几个，服务端执行前还会再查一次身份
- 改稿分四种：append 末尾追加、prepend 开头插入、replace 整篇重写、patch 精确替换一段。patch 要求原样给出要改的那段原文，找不到或者出现了两次都会报错，不会改错地方
- 删除是挪进 `.trash/`，不是 rm；每次改动前也留一份。文件名从标题推出来，只留中英文数字短横，算出来的路径必须落在 `_posts` 里
- 发布就是 `hexo generate` + rsync，十秒。用 `execFile` 异步跑，同步的话整个 Node 进程会卡住，别人正在聊的那条也跟着停
- 回收站会自己清。启动扫一次、之后每六小时一次：超过 30 天的删掉，份数超 300 的只留最新的。年龄按文件名里的时间戳算，不看 `mtime`——`renameSync` 保留原文件的修改时间，一篇 2025 年的文章今天被删，按 mtime 算会当场清掉，回收站等于没有
- 歌词会认短句了。一两个字、活不到 0.9 秒的句子并回下一句：《我们》里 `[01:00.64] 当` 只占 0.31 秒，滚动动画要 600ms，跑一半就被顶掉，两列从半路弹回原位，看着就是闪一下。现在并成「当阳光洒落在我们身旁」，从「当」出口那一刻开始显示，完整 3.49 秒
- 动画档位改用「这句能活多久」判断，不再用「上次绘制到现在」。低于 1.2 秒不走滚动（跑不完），走淡切，淡入时长按存活时间缩，90 到 180ms 之间。合并后这首歌只剩「什么时候」（1.13 秒）和「不再追求」（1.05 秒）两句走淡切，其余全部滚动
- 有了沉浸听歌页。点左下角播放器的封面进去，整页交给当前这首：同一张封面模糊铺满、压暗、极慢地缩放，中间是封面本体、歌名、进度和控制，竖排歌词从左边挪到右半边，和封面分坐两侧。Esc 或右上角退出
- 背景的主色从封面里取：canvas 读 24×24 像素，剔掉过黑过白的（它们在模糊背景里贡献的是灰不是颜色），剩下的取平均，再往白里提 34% 当强调色。进度条和频谱都用这个色，换首歌整套跟着变
- 频谱是真的在动，不是装饰。给 `audio` 加了 `crossOrigin`，用 Web Audio 的 `AnalyserNode` 取频率数据，底部一条 64 格的细柱子，`mix-blend-mode: screen` 叠在背景上像光不像图。暂停时压到 0.1 透明度
- 音乐页从「半透明卡片盖在插画上」换成纸。以前卡片是 `rgba(255,255,255,0.64)` 加 18px 模糊，云朵直接透过来，13px 的灰字和背景糊成一片；现在是一张几乎不透明的暖白纸，插画只在卡片外面露出来。歌单标签从八色胶囊改成一条目录：细线贯穿、选中压一道墨，和下面的列表接成同一张纸
- 音乐页第二版，整页一张纸。hero、标签条、列表接成连续的一张，阴影用 `drop-shadow` 打在容器上——只认整张纸的外轮廓，接缝不漏影子。歌单标题换宋体，和沉浸页的歌名同一支笔；右边用空心描边印一个大号期数（曲目数），当目录页的页码，头部不再空着。列表改索引式：歌手右对齐，中间的空是故意的留白

**踩的坑**

- systemd 的 `ProtectSystem=strict` 把整个文件系统挂成只读，记忆写盘报 `EROFS`，但只打日志不报错——对话能用（内存在），一重启就全丢。得加 `ReadWritePaths=/opt/l2d/data` 并把目录 chown 给 `www-data`
- 改记忆文件后直接 `systemctl restart` 没用：旧进程收到 SIGTERM 时会把内存里的 `saveMem()` 写回去，把你刚改的覆盖掉。得先 `stop` 再改再 `start`
- 验证 180ms 的透明度动画不能靠连续采样：headless 下 rAF 帧率低，第一次采样就已经是 t=150ms，看着像「瞬间到 1」。要用 `anim.pause()` + `anim.currentTime = 90` 手动定格
- 淡切第一版用 CSS transition（设 0.18 → 强制回流 → 清空），快歌里连续切换时浏览器把这几步合并成一次样式计算，起点没落地，`opacity` 一直是 1，等于还是硬切。改用 Web Animations 才生效
- 两轮的文字直接拼在一起会粘成病句。第一轮「我先把这两段调出来看看，别凭印象编」加第二轮「共同点是没有报错」，拼起来读成「别凭印象编共同点是没有报错」。prompt 里禁止在调工具前说话（「开口就说结论」），再在轮次之间补一个 `\n\n` 的 delta 兜底
- 气泡的 `.l2d-text` 没写 `white-space: pre-wrap`，模型输出的 `\n\n` 全被折叠成空格，分好的段白写了。加上之后 168px 高度里能放五六行，再多有滚动
- 记忆合并第一版规则写「同一件事换了个说法就合并」，模型只合了最像的一组。改成给具体例子——「在改歌词同步」「字幕跟不上歌」「歌词高亮提前结束」是同一件事——才合得动。规则要举例，光说原则没用
- `createMediaElementSource` 会把 `audio` 的输出从默认路径上摘下来，必须自己 `connect` 回 `destination`，否则整首歌静音。而且这一步要先做，再做 analyser 的连接——顺序反过来的话 analyser 那步万一抛错，声音就永远出不来，用户只会觉得「点了没声」
- 给 `audio` 加 `crossOrigin` 有风险：源不回 `Access-Control-Allow-Origin` 就会被当成加载失败（`error.code === 4`）。加了降级——检测到 code 4 就去掉 crossOrigin 重试一次，宁可没有频谱也不能没声音。网易云 CDN 实测回 `Allow-Origin: *`，正常走不到这一步
- 沉浸页的歌词层第一版 z-index 写成 3，比覆盖层的 1000 还低，整块被压在底下看不见。覆盖层里的东西要盖过它，z-index 得给到 1000 以上
- 背景 `blur(70px)` 太狠，一张蓝灰山景被糊成一块纯色，完全看不出是封面——「沉浸」变成了「换了个深色底」。降到 44px、提亮到 0.52 才认得出
- 从「追加」改成「重写整份」之后，模型返回空数组会把记忆清空。加了保护：本来有记忆、它却返回空，多半是理解错了，保留旧的。宁可少记不可错删
- 用户消息原来是蓝底白字，`#49b1f5` 上白字对比度只有 2.6:1，小字看不清。改成淡蓝底深字（荧光笔那种），对比度到 8:1
- 手账便签的预览页里，我手写 HTML 的缩进被 `.l2d-say` 上的 `white-space: pre-wrap` 渲染成了空白，一条消息撑满整个气泡。线上是 JS 建节点，没这个问题——但说明 pre-wrap 只该给段落，不该给容器
- Chrome headless 连着截两张图时，第二个实例会连到第一个的 daemon 上，截到的是旧页面。深色主题因此「看起来没生效」，单独跑一次就正常
- systemd 的 `MemoryMax=128M` 直接把 `hexo generate` 杀了——它峰值三百兆。上限不是预留，闲时还是二十几兆，改到 512M 就行
- 服务跑在 `www-data` 下，`/var/www/blog-source` 是 root 的，写不进去。chown 给 www-data 之后 root 的 git 会报 `dubious ownership`，得加 `safe.directory`
- `.bin/hexo` 的 shebang 是 `#!/usr/bin/env node`，服务里 PATH 不一定有 node。改成用 `process.execPath` 跑 `node_modules/hexo/bin/hexo`，不依赖 shebang
- `tr.acts = pending.map(...)` 是赋值不是追加，把前面 push 的写操作记录全盖掉了。trace 里只看得到浏览器动作，看不到她刚改过哪篇
- 不带历史单独发一句「删吧」，模型不知道删什么——它会从记忆里的 `lastTopic` 找，而 `lastTopic` 可能记的是一次根本没发生的删除。工具调用是无状态的，上下文只能靠前端传的 `messages`
- 回收站清理第一版差点写成看 `mtime`——`fs.renameSync` 不改修改时间，删除时间和文件年龄是两回事，写错的话删掉的老文章会当场被清掉
- 清理只在启动和每六小时跑，没有定时器精度要求；`setInterval(...).unref()` 让它不拖住进程退出
- 短句合并只往下一句并，不往上一句：「当」是「当阳光洒落…」的第一个字，挂到上一句末尾就变成「…最初的模样当」，反了
- 合并时要把整句的时间戳一起提前到被并那句的位置，否则字幕会比歌声晚 0.31 秒——「当」已经唱出来了，字幕还在上一句
- 用 `sed` 改含中文的 JS 注释会把多字节字符按字节改坏：`下一句` 变 `不一句`、`连续` 变 `连绝`、句号后面多出个 `s`。中文文件一律走 Python 读写，不用 sed
- 标签条去掉胶囊底色之后直接压在森林插画上，几乎看不见——「变安静」差点变成「消失」。降噪的同时得给它一块纸底，透明不等于克制
- 改完 CSS 截图还是旧样子，一度以为样式没生效：Chrome 用的是同一个 `user-data-dir`，缓存住了旧样式表。CDP 里要 `Network.setCacheDisabled(true)` 才看得到真实结果
- 首屏封面截出来是个空白框：图片 `complete` 为 true、`is-ready` 也加上了，但 `Page.captureScreenshot` 拍在解码之前。截图前跑一遍 `img.decode()` 才稳
- 断言里的引用数凭印象写：`--mp-serif` 写成 2 处，实际标题、期号、手机端共 3 处，补丁跑到一半断下来，CSS 写完 JS 没写。断言之前先把真实引用数数一遍
- `.mp` 上加 `filter: drop-shadow` 打整纸阴影，`filter` 会创建包含块，fixed 元素挂在里面会被拽住——查过 dock 一直挂在 `body` 下才敢这么做

## 2026-11-15

- 没人理的时候，她会从右边踱出来一点再退回去，每 24～46 秒一次，每次一两秒。只往左走——她本来贴着右边缘，往右会走出屏幕
- 这套模型没有腿部骨骼（只有 `ParamBodyAngle*` 和 `Param_arm_*`，而且都是物理输出，写了会被盖），迈不了腿，所以只能整体平移。让它不像「滑行」靠三件事：平移时叠一个上下起伏，频率按小碎步的节奏、两端收小；头朝行进方向偏；起步和收尾缓、中间快
- 气泡原来是 `position: fixed`，走动一加就出问题：带 `transform` 的祖先会成为 fixed 子元素的包含块，`.l2d` 一动气泡就跑到另一个坐标系里去了。改成 `position: absolute` 相对 `.l2d` 定位，容器走气泡跟着走，一步不用额外算
- 鼠标凑过来就站住，不然「朝行进方向看」和「抬眼看你」会打架；滚页面的时候也不走，会分神；手机上不走，屏幕窄，走两步就挡正文
- 踱步后来又撤了：模型没有腿骨，脚没法交替，只能靠整体平移加上身晃动去凑。调了步频、速度、摆臂、胯部、尾巴、裙摆，姿态是像了，但脚一直并着滑，反而比不动更出戏。相关代码删干净，不留开关
- 看板娘可以拖到任意位置，位置存本地。用 `translate3d` 不用 left/top——容器本来就是 right:0; bottom:0，换成 left/top 还要在 resize 时重算，translate 不参与布局，拖的时候不触发重排
- 拖动和点击靠位移阈值分开：超过 4px 才算拖，否则还是点击。拖完那个 click 必须吞掉，不然一松手就弹出气泡。用 `setPointerCapture`，拖出热区、拖到屏幕边上都不会断
- 拖动范围里预留了气泡的位置。气泡是相对 `.l2d` 的 absolute，比容器宽（258 vs 240）而且往上长：拖到左上角后点她，气泡会整个跑到屏幕外，看着就像「点了没反应」。横向按 (240 − 宽/2) 算，纵向留 200px，窗口缩小时 resize 里再夹一道
