## 2026-11-13

**新增**

- 右下角接进 Live2D 看板娘，形象是「大肥鱼」——DeepSeek 蓝鲸 logo 的网友拟人版。模型用 B 站「香甜小兔子」免费配布的那套（UID 431301506），1.2MB 的 moc3，174 个参数
- 中间试过神宫凉子那套官方公皮，8 个动作、23 个表情都齐，但 moc3 有 15.7MB。服务器出口只有 3～4Mbps，第一次要下三十秒，权衡之后换成这套轻的
- 两套都是 Cubism 5 导出的（moc3 version 5），原来的 Cubism 4 core 读不了，报错只有一句 `Unknown error`，从提示里完全看不出是版本问题。换成官方 5.1 版的 core 才通；换完之后旧的 4.x core 再没人引用，删了
- 贴图原始 8192×8192（29MB），降到 2048 存 webp，385KB。页面上人物只有 300px 宽
- 眨眼组原本是空的，补上 `EyeBlink`（`ParamEyeLOpen` / `ParamEyeROpen`）和 `LipSync`（`ParamMouthOpenY`）之后才会眨眼、才能跟着说话动嘴
- 水印是两套部件，靠 `Paramcol_3` 切
- 作者没给 motion 文件，动作是自己写的。本来想写成 motion3.json，但 pixi-live2d-display 一旦开始播 motion 就跳过自动眨眼，她会在两秒内一直瞪着。改成在主循环里用缓动函数推参数
- 写参数的位置试了三处才找对：ticker、渲染前、`update` 前后都不行——库在 update 末尾会 `loadParameters()` 把参数还原。最后挂在 `beforeModelUpdate` 上：物理算完、`coreModel.update()` 还没算网格，中间就这一条缝
- 七套动作：点头、摇头、歪头、思考、惊讶、打盹、开心。点她随机一个，发问时歪头想，答完点一下头，自动打招呼时笑
- 后来又照 Hiyori 那十段待机的路子添了六套：瞥一眼、叹气、鼓嘴、受惊、害羞（带脸红）、打哈欠。它的动作曲线主要就是头角度、眼球偏移、眉毛嘴角，加上烘进曲线里的眨眼——沿这个思路做，不需要新素材
- 眼球（`ParamEyeBallX` / `Y`）能单独动，所以「瞥一眼」是眼睛先过去、头慢半拍跟上，比整体转头自然
- 半闭眼不可靠：眼皮是物理从 `ParamEyeLOpen` 拖过去的，写 0.6～0.8 这种中间值会被上一帧的物理状态拖成完全闭合，看着像眨眼。叹气、鼓嘴这类只用「全开 / 全闭」
- 脸红走表情参数 `PARAM_EXP4`，写 1 就是满格，可以按帧淡入淡出
- 没人理的时候每 14～28 秒自己动一下（瞥一眼 / 叹气 / 歪头 / 打哈欠 / 鼓嘴）。不做常驻循环：常驻会一直压着光标跟随，鼠标一动她就僵在那里
- 动作之间会「闪」一下：原来每帧直接把参数覆盖成动作值，动作一起头就从光标跟随的姿势跳到 0 度，一落又弹回去；两个动作相撞时也是先归零再起。改成写差值、叠在模型算好的姿势上，再用 70ms 左右的时间常数淡入淡出，打断时从当前值直接往新目标走，中间不经过 0
- 叠加会超范围（光标在角落时 focus 已经 +20°，再叠 18° 就破了），所以写之前按参数上下限夹一道
- 加了三种鼠标互动。一是悬停：鼠标移到她身上，会抬眼看你、眉毛扬一下、嘴角松一点。走单独一条 180ms 的平滑曲线，比动作的 70ms 慢，不然鼠标一扫过去她像被弹了一下
- 二是摸头：头顶单开一块 104×96 的热区。原来那块 150×320 的身体热区只到脖子——人物是铺满整个画布高度的，头顶那 110px 根本没被盖住，点头顶其实没反应
- 摸头会闭眼笑或脸红低头，台词是单独一套（「……干嘛。」「头发要乱了。」），而且不抢输入框焦点：摸头是顺手一下，不是要跟她说话
- 三是移出窗口视线回正：监听 `pointerout` 且 `relatedTarget` 为空，把 focus 归零。不处理的话她会一直斜着眼睛盯着你最后停的那个角落
- 两块热区之间用 80ms 延迟关闭传递悬停状态，避免从头顶滑到身体时中间那一下 leave 把状态抖断
- 看板娘的台词全部去掉了句号：打招呼、摸头、页面语境、异常提示，一共 21 处。短句之间原本用句号的改成逗号（「来了。随便看。」→「来了，随便看」），问号和省略号保留。句号收尾会让短句看着像书面语，她要的是随口说的感觉
- 网页人设 `/opt/l2d/persona.txt` 里也加了一条「句末不画句号」，并把七个对话示例一并改了。人设是启动时读进内存的，改完要 `systemctl restart l2d`
- 修了视线跟随：它其实一直是坏的，只是坏得不明显。`model.focus()` 收的不是 -1~1，是舞台坐标——传归一化值进去，等于说「画布左上角附近那个点」，内部 `toModelPosition` → 归一化 → `atan2` → 取单位向量，结果恒定指向左上。所以她一直斜着眼看左边，鼠标怎么动都不变
- 这个 API 也永远算不出「正前方」：它返回的是单位向量，`focus(0,0)` 同样指左上。回正得直接调 `focusController.focus(0,0)`
- 改成直接驱动 `focusController`（它收的才是 -1~1），方向按模型中心算。归一化不能统一除视口半宽：她在右下角，右边只剩一百多像素，统一除的话鼠标推到最右也只有 0.1 的偏移，看着像没反应。改成按「到哪一侧边界」分别归一化，左右上下都能跑满
- 头部三轴的符号是实测的：`ParamAngleY` 正 = 低头，`ParamAngleX` 正 = 转向画面左侧，`ParamAngleZ` 正 = 向左歪头。手臂和身体角度都是物理输出，写了也会被物理盖掉，所以动作只用头部和五官
- 说话时按正弦波推 `ParamMouthOpenY`，不发声，只给个口型节奏
- moc3 走 `gzip_static` 预压缩；`/live2d/` 整段给一年 immutable 缓存
- 模型 1.8MB，慢网也要几秒，所以先摆一张同模型、同排版渲染的静态图顶着，底下一条加载条来回走，就绪后淡入换掉
- 渲染用 pixi 6 加 pixi-live2d-display 0.4（cubism4 构建），引擎和模型都自托管，不走 CDN
- 首屏 load 之后 2.6 秒才拉模型。手机上一开始只给右下角一个小圆钮，点了才下载
- 对话走后端 `/api/chat` 转 `127.0.0.1:3002`，流式返回。人设是访客版，跟站内 skill 那份不是一回事
- 限流两层：nginx 每分钟 20 次；应用层每 IP 每分钟 4 条、每天 40 条，全站每天 800 条

**修复**

- 自建解析源被限流时，前端原来会静默切到匿名公共源，会员曲目在那边只剩 30 秒试听。现在 429 和 5xx 一律当作「暂时忙」，同源退避重试三次（0.8 / 1.6 / 3.2 秒），仍失败就保留现有列表，不再降级
- 首页诗句接口一直报 403，查下来不是鉴权问题，是限速：打开页面时用 3 个并发一口气打 8 个请求，一秒内打完，后面的全被拦。实测这接口按 IP 限速，每秒超过两次就 403，而且 403 的响应体是空的，控制台里只看得到一个光秃秃的状态码，看不出原因
- 现在所有请求排成一条串行队列，两次之间至少隔 700ms；取到的句子存 localStorage，下次打开先用旧的直接开播，有缓存时一次都不请求；一旦撞到 403 就停手，不再继续打——越打只会限得越久
- 首屏取句从 8 句降到 5 句，补句从 2 句降到 1 句。实测首次访问 5 个请求全 200，刷新后只补 1 个
- 对话框改成了一朵云，停在头顶正上方，底下一串递减的小圆当尾巴，像从头顶冒出来的。形状是「主体 + 三个鼓包 + 尾巴」拼的，只放两个鼓包时中间会留一大段平顶，看着像盒子贴了两个球
- 拼接形状的投影不能用 `box-shadow`——每个形状各投一份，接缝上会叠出脏边。得用 `filter: drop-shadow`，它按合并后的轮廓算阴影，看上去才是一整朵
- 但 `filter` 会把文字一起光栅化，13px 的字会发虚。所以拆两层：`.l2d-cloud` 只管形状和投影，`.l2d-inner` 放文字和输入框，后者不参与滤镜
- 气泡的 `bottom` 直接取 `var(--l2d-h)`：人物铺满整个画布高度、底边贴底，所以画布顶部距屏幕底正好是这个值，气泡底边停在那就正好在头顶。之前凭感觉写了 0.9 倍，结果掉到头顶下面去了
- 出现动画从尾巴那一点缩放（`transform-origin` 对准尾巴），配 `cubic-bezier(0.34, 1.56, 0.64, 1)` 带回弹，0.42 秒落定；收起走 0.18 秒，快一些
- 输入框去掉了方框，改成胶囊淡底。方框子在圆润的云里太硬，眼睛会先看到它
- 顶边原来是三个鼓包，中间会露出一段直线——看着像盒子贴了几个球。改成四个首尾相压：一个圆在顶边上的可见宽度是 `2w·√(k−k²)`（w 是直径，k 是露出高度占直径的比例），相邻两个的弦得压住，顶边才完全由弧线组成
- 鼓包的位置和大小都改百分比，露出高度用 `translateY` 的百分比（鼓包是正方形，`aspect-ratio: 1`，所以百分比就是相对自身高度）。这样宽屏窄屏形状一致，不会因为气泡变宽而变扁
- 没人理的时候，她会从右边踱出来一点再退回去，每 24～46 秒一次，每次一两秒。只往左走——她本来贴着右边缘，往右会走出屏幕
- 这套模型没有腿部骨骼（只有 `ParamBodyAngle*` 和 `Param_arm_*`，而且都是物理输出，写了会被盖），迈不了腿，所以只能整体平移。让它不像「滑行」靠三件事：平移时叠一个上下起伏，频率按小碎步的节奏、两端收小；头朝行进方向偏；起步和收尾缓、中间快
- 气泡原来是 `position: fixed`，走动一加就出问题：带 `transform` 的祖先会成为 fixed 子元素的包含块，`.l2d` 一动气泡就跑到另一个坐标系里去了。改成 `position: absolute` 相对 `.l2d` 定位，容器走气泡跟着走，一步不用额外算
- 鼠标凑过来就站住，不然「朝行进方向看」和「抬眼看你」会打架；滚页面的时候也不走，会分神；手机上不走，屏幕窄，走两步就挡正文

## 2026-11-12

**修复**

- 积压的 5 个提交推不上去：服务器没有 GitHub 写权限，`git push` 报 `could not read Username`。改用仓库级 SSH 部署密钥（ed25519，只授权 `blog` 仓库写权限），远端从 HTTPS 切到 `git@github.com`，仓库内用 `core.sshCommand` 指定密钥，未改全局 `~/.ssh/config`，不影响原有的 `github_actions` 密钥
- 换凭证后首次推送成功（`dfd7304..ed59764`），GitHub Actions「Deploy to GitHub Pages」通过
- 图标全部空白：Font Awesome 走 `cdn.jsdelivr.net`，国内网络时常拉不到。改成自托管（`source/libs/fontawesome`，6.7.2，只留 woff2，共 388 KB），与之前 pjax 换本地是同一个理由
- 名片里 GitHub 图标看不见：SVG 蒙版用的是品牌深灰 `#24292e`，深色卡片上等于隐形。深色主题改用浅色，浅色主题仍保留品牌色
- 滚动条亮带：自定义的 8px 主题色滑块在深色底上过于扎眼，改为 6px、默认 16% 不透明度，只在悬停或拖动时提亮
- 点视口边缘会冒出一条贴边亮线：星尘涟漪的光核正好生在画布边界上，半个径向渐变被 canvas 直接裁掉，看起来像渲染故障。现在生成点从边缘内收 28px，并给粒子加了「距边界 26px 内渐隐」，任何绘制都不会被硬切
- 名片里 GitHub 和邮箱两个圆形按钮高度对不齐：一个用 SVG 蒙版、一个用字体字形，同一个 1em 盒子，字形的墨迹只有 0.75em 高（实测 20.5px 对 15.8px）。现在两个都走内联 SVG 蒙版，信封靠蒙版自身比例收到 0.94em，横长 1.18em

**功能**

- 音乐页加歌词字幕：一次只显示一句，居中，按 LRC 时间轴二分查找当前句。换句先淡出 210ms 再换字淡入；间隔不到 1.1 秒的直接换
- 前奏还没唱到第一句时，首句用淡色摆着当预告。否则前奏长的歌这块要空二十几秒，看着像没加载
- 纯音乐不做空态，显示「纯音乐」加作曲 / 编曲。安静歌单 20 首里 16 首没有歌词，这是常态
- 服务端单开一条 `type=lyric` 路由，缓存 24 小时、独立一份 Map。主缓存只有 64 条，一个 51 首的歌单光歌词就能把播放地址全挤掉
- 歌单接口原来不带 `songId`，前端取不到曲目 id 就发不出歌词请求。现在每条多一个 `songId`

**部署**

- 启用 HTTPS：Let's Encrypt 自 2026-01 起支持纯 IP 证书，为 `47.98.233.253` 签了一张，nginx 改为 80/443 双端口服务
- IP 证书只能走 `shortlived` 档，160 小时就到期，因此加了 systemd 定时器每天两次续期，续期后自动 reload nginx；`--dry-run` 演练通过
- 没有强制 HTTP 跳 HTTPS：证书寿命只有 6 天，续期一旦断链，强制跳转就让人连退回 HTTP 的机会都没有

**内容**

- 补齐上一批未提交的改动：新增《看板娘入住博客啦》与两张配图，五篇旧文改口吻重写
- 名片头像与导航栏图标统一换成新插画：直接用原图（792×783）不做二次裁切，图本身是圆形构图，四角白底正好被 `border-radius: 50%` 的圆形遮罩切掉；两处引用同一个 URL，浏览器只下载一次
