再打开是 2026 年 3 月。`npm install` 直接报错，主题停在十个月前的版本，`hexo s` 起来一片空白。断断续续修到 10 月，才算能看。

## 这个站

站名「风月酌酒」，看风景，喝点酒，顺便写点东西。起名的时候没想太多，就觉得这四个字念着顺。

内容分四块。

- **编程**，学习笔记、踩坑记录、工具折腾
- **动漫**，看过的番，偶尔写点感想
- **游戏**，玩过的东西
- **生活**，没什么主题的随笔

编程会占大头，因为我大部分时间在跟代码较劲。另外三块几个月才动一次，我不打算硬凑。

有人说这种站叫数字花园。我更愿意把它当记事本，半年后忘了某个配置怎么改，回来翻一翻。顺带对别人有用，那算赚了。

## 技术选型

| 层 | 选择 | 为什么是它 |
| --- | --- | --- |
| 生成器 | Hexo 8.1.2 | 纯静态，没有数据库和后台。写博客已经够费劲，不想再维护一台服务器 |
| 主题 | Butterfly 5.7.1 | 卡片式布局，功能齐，社区还在更新 |
| 部署 | GitHub Pages + Actions | 推代码就发布，不用买服务器，也不用管证书 |
| 搜索 | hexo-generator-search | 本地搜索，不依赖第三方服务 |
| 评论 | 暂未启用 | 先用 GitHub 和邮箱联系，等人多了再说 |

静态站的好处就一条，不用管服务器。代价是没有后台，写文章得在本地写好再推上去。我本来也是在本地的编辑器里写，这个代价可以接受。

## 从零搭起来

### 环境

```bash
node -v          # 建议 20 或 22 的 LTS
git --version
```

Node 用 LTS。Hexo 8 要求 20.19 以上，但别去追 Current 版本，偶尔会撞上依赖不兼容。

### 初始化

```bash
npm install -g hexo-cli
hexo init blog
cd blog
npm install
```

### 装主题

Butterfly 用 submodule 引入，主题能独立更新，也不会和自己的配置搅在一起。

```bash
git submodule add https://github.com/jerryc127/hexo-theme-butterfly.git themes/butterfly
git submodule update --init --recursive
```

然后改两处。

```yaml
# _config.yml
theme: butterfly
```

```bash
# 把主题自带配置复制到根目录，以后只改根目录这份
cp themes/butterfly/_config.yml _config.butterfly.yml
```

这一步别省。`_config.butterfly.yml` 放在根目录，主题目录保持干净，以后 `git submodule update` 拉新版本，配置不会丢。

### 固定链接

Hexo 默认拿标题生成 URL。标题是会改的，链接不该跟着改，不然外面引用全断。

```bash
npm install hexo-abbrlink --save
```

```yaml
# _config.yml
permalink: post/:abbrlink.html
abbrlink:
  alg: crc32   # crc16 或 crc32
  rep: hex     # dec 或 hex
```

`abbrlink` 在第一次生成时算出来就定死了，之后改标题、改分类，链接都不动。已经发出去的文章，别去动这个值。

### 本地搜索

```bash
npm install hexo-generator-search --save
```

```yaml
# _config.yml
search:
  path: search.xml
  field: all
  content: true
```

```yaml
# _config.butterfly.yml
search:
  use: local_search
  placeholder: 搜索文章
```

### 预览

```bash
npx hexo clean && npx hexo generate
npx hexo server -p 4000
```

打开 <http://localhost:4000>。`hexo server` 会盯着文件改动，改完自动重新生成。

### 部署

站点分两个仓库。源码仓库放 Hexo 源文件，产物仓库（`<用户名>.github.io`）放构建出来的 `public/`，Pages 从后者读。

中间用 GitHub Actions 串起来。`.github/workflows/deploy-pages.yml` 大致四步。

1. `actions/checkout` 拉源码，记得带 `submodules: recursive`，否则主题目录是空的
2. `actions/setup-node` 装 Node
3. `npm ci && npm run build`
4. 用 Deploy Key 把 `public/` 推到产物仓库

认证这块一开始用的是 PAT，token 的作用域怎么配都不对，push 一直被拒。换成 Deploy Key 之后一次配完，再没管过。

```bash
ssh-keygen -t ed25519 -C "deploy-key@example.github.io" -f .deploy-key/id_ed25519 -N ""
```

公钥贴到产物仓库的 Settings → Deploy keys，**记得勾 Allow write access**。私钥贴到源码仓库的 Settings → Secrets → Actions，命名 `DEPLOY_KEY`。

## 目录结构

```text
blog/
├── _config.yml              # Hexo 主配置
├── _config.butterfly.yml    # 主题配置（和主题源码分开）
├── source/
│   ├── _posts/              # 文章
│   ├── _data/link.yml       # 友链
│   ├── css/custom.css       # 自定义样式
│   └── js/universe.js       # 夜间星空特效
├── themes/butterfly/        # 主题（git submodule）
├── scripts/                 # 自定义 Hexo 脚本
└── .github/workflows/       # 自动部署
```

## 自定义样式放哪

主题是 submodule，直接改里面的文件，下次更新就没了。样式一律写在 `source/css/custom.css`，通过 `_config.butterfly.yml` 的 `inject.head` 注进去。

```yaml
inject:
  head:
    - <link rel="stylesheet" href="/css/custom.css">
```

它排在主题的 `index.css` 后面，同优先级下能盖住主题样式，升级主题也不会丢改动。

夜间星空同理。`source/js/universe.js` 是个 canvas 粒子脚本，只在 `data-theme="dark"` 时画。2025 年 5 月刚加的时候没处理切回白天的情况，屏幕上留着一层星星擦不掉，后来补了清空画布才正常。

## 几个坑

### 克隆下来页面全白

九成是主题没拉下来。`themes/butterfly` 是 submodule，普通 `git clone` 不会自动拉。

```bash
git submodule update --init --recursive
```

### 样式或图片 404

先看 `_config.yml` 里的 `url`。站点如果挂在子路径下，还要确认 `root`，不然所有绝对路径都会错位。

### 改了标题链接就变了

说明没开 `abbrlink`。开了之后链接由 `abbrlink` 字段决定，和标题脱钩。

### 文章页空白，生成的文件是 0 字节

这个坑花的时间比前面所有加起来都多。根因是 `hexo-util` 的 `Pattern` 没做首尾锚定，把主题的样式表当成了布局，渲染文章时拿 stylus 文件当 pug 模板用。完整排查过程单独写了一篇，[在这里](/post/15076.html)。

搭这个站花了三个晚上。写文章的时间是它的几十倍，而且大部分时候什么都没写出来。

2025 年 5 月更新完主题，这里空了十个月。每次打开编辑器，都觉得没什么值得写的。

后来发现能写的东西都在过程里。那个 0 字节的 bug 就是，不记下来，明年我肯定想不起 `Pattern` 是怎么回事。
